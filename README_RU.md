# Home Lab — 6 демонстрационных проектов

Это личные учебные проекты для портфолио, а не выполненные клиентские заказы. Все примеры устройств, адресов и резервных копий синтетические. Код создан с помощью AI; перед предложением клиенту разберись в логике и проверь его на своих данных.

## Быстрый запуск на Windows
1. Распакуй архив полностью в отдельную папку.
2. Открой START_HERE.html двойным нажатием. Сайты работают локально без установки.
3. Для скриптов нужен установленный Python 3.10 или новее. В папке проекта открой PowerShell.
4. Выполни: `py run_demo.py`
5. Результаты появятся в новой папке runs/дата-время. Открой inventory/report.html и backups/report.html внутри неё.
Если команда py не найдена, попробуй python. На Linux: `python3 run_demo.py`.
Никакие API-ключи, подписки, дополнительные Python-пакеты или доступ к твоему серверу не нужны.

## 01. Сортировщик загрузок {#downloads}
Ситуация: после занятий накопились документы, скрипты, архивы и лабораторные файлы.
Вход: samples/downloads. Результат: Documents, Scripts, Tables и другие категории.
Предпросмотр: `py tools/sort_files.py samples/downloads output-downloads`
Копирование: `py tools/sort_files.py samples/downloads output-downloads --apply`
Исходники не удаляются. Вложенные папки обрабатываются, символические ссылки пропускаются. Разные файлы с одинаковыми именами получают суффиксы __1, __2. Повторный запуск не копирует уже найденный идентичный файл. Идентичные файлы с разными именами НЕ объединяются.
После копирования проверяется SHA-256. В терминал выводится JSON-журнал. Сохрани его: добавь `> downloads-log.json` к команде.
Чему учит: pathlib, аргументы командной строки, безопасная работа с файлами, хеширование.
Показ клиенту: открыть исходную папку, показать план, выполнить копирование и открыть категории.
Граница: локальная утилита для доверенных папок, не служба мониторинга. Это не атомарная транзакция: при ошибке часть копий может остаться; оригиналы остаются на месте. Не запускай параллельно несколько экземпляров в одну выходную папку.

## 02. Архив конфигураций сети {#configs}
Ситуация: нужно хранить экспортированные конфигурации Cisco/MikroTik по устройствам и месяцам.
Имена: sw01_2026-11-07.cfg, rb01_2026-11-07.rsc. Поддерживаются .cfg, .conf, .rsc; имя устройства: буквы, цифры и дефисы.
Предпросмотр: `py tools/sort_files.py samples/configs output-configs --mode configs`
Копирование: `py tools/sort_files.py samples/configs output-configs --mode configs --apply`
Результат: sw01/2026-11/sw01_2026-11-07.cfg. Некорректные даты и неподходящие имена пропускаются с указанием причины.
Чему учит: регулярные выражения, проверка дат, структура архива, контроль целостности.
Показ клиенту: три пригодных конфига распределяются; notes.txt и файл с невозможной датой пропускаются.
Граница: утилита НЕ подключается к оборудованию, не экспортирует и не восстанавливает конфиги. Примеры — короткие текстовые заглушки; не загружай их на реальные устройства. Реальные конфиги могут содержать секреты; не публикуй их в портфолио.

## 03. Очистка инвентаризации Excel / CSV
Ситуация: в списке VM появились дубликаты, разные регистры имён, неправильные IP и конфликтующие записи.
Запуск: `py tools/tables.py inventory samples/inventory.csv output-inventory`
Колонки: hostname, ip, role, ram_gb. RAM — положительное число; IP — IPv4 или IPv6.
Результат: clean.csv, issues.csv, summary.json и report.html.
В демонстрации: 8 входных строк, 5 принятых строк, 4 замечания; сумма RAM в принятых строках 20 GB.
Важно: конфликт IP отмечается, но запись остаётся в clean.csv, чтобы не потерять данные. Количество замечаний — не число отброшенных строк. Сумма RAM — сумма строк инвентаря, включая хост и гостевые VM; это НЕ оценка физической ёмкости и не проверка переподписки RAM.
Чему учит: нормализация, валидация, поиск повторов, отчёт об исключениях.
Показ клиенту: сравнить исходные строки с clean.csv и issues.csv, объяснить каждое замечание.

## 04. Отчёт по резервным копиям Excel / CSV
Ситуация: из экспорта заданий нужно понять успешность запусков и последние сбои по VM.
Запуск: `py tools/tables.py backups samples/backups.csv output-backups`
Колонки: job_id, vm, started_at, status, duration_min, size_gb.
status: success или failed. started_at: ISO 8601 с часовым поясом, например 2026-11-07T02:00:00+00:00.
Результат: clean.csv, issues.csv, summary.json, report.html.
В демонстрации: 6 валидных заданий, 4 успешных, 2 неудачных; успешность 66.7%, объём успешных запусков 18 GB. Последний записанный бэкап dc-01 неуспешен. Повтор job_id и некорректная дата исключены и попали в issues.csv.
Последний запуск определяется по времени, не по порядку строк. При одинаковом времени берётся первая запись. Имена VM чувствительны к регистру. Повторный job_id исключается после первой принятой записи.
Граница: нет подключения к Proxmox, проверки давности или восстановимости бэкапов. VM без записей не обнаруживаются. Успешность считается по запускам, не по VM. Объём — сумма экспортированных size_gb успешных заданий, не фактическое занятое место после дедупликации.

## Поддержка Excel в проектах 03–04
Вход: CSV (запятая, точка с запятой или табуляция, UTF-8) и .xlsx с данными на ПЕРВОМ листе. Команда та же, замени путь samples/inventory.csv на свой .xlsx.
Первая строка — заголовки, без титульных строк и объединённых ячеек. Входные ячейки должны содержать значения; формулы отвергаются. Даты в .xlsx храни ТЕКСТОМ ISO 8601, не числовыми датами Excel.
Не поддерживаются .xls, .xlsm, зашифрованные файлы и файлы свыше 20 MB в распакованном виде. CSV обрабатывается в памяти, демо рассчитано на небольшие таблицы.
Выходные таблицы — CSV UTF-8 с BOM, а не оформленные .xlsx. Они открываются в Excel. Если всё в одной колонке: Данные → Из текста/CSV → разделитель «запятая». Строки, похожие на формулы, экранируются апострофом.
Существующая выходная папка не перезаписывается: укажи новое имя или используй run_demo.py, который создаёт новую папку автоматически.

Открой файл в браузере или перейди с START_HERE.html. HTML, CSS и JavaScript без сборки и библиотек.

Не называй это реальными заказами, не придумывай отзывы. Перед первым заказом повтори демонстрацию на своём ПК и измени один параметр самостоятельно.

## Проверки
`py -m unittest discover -s tests -v`
Проверяются сохранение оригиналов, коллизии имён, повторный запуск, dry-run, запрет вложенной выходной папки, отбор конфигов, итоги отчётов, нечисловые данные и экранирование CSV. Отдельно проверяется чтение минимального XLSX и отказ на формулы.
Проверки выполнены в Linux с Python. Запуск на твоём Windows и открытие в Microsoft Excel требуют локальной проверки. HTML-сайты адаптивны; все данные демонстрационные.
